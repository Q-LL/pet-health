# v1 开发计划

2026-10-10 定稿。本文取代旧版的开发状态文档（见 `legacy-v0` 标签）。文案和语气见 [COPY_DRAFT.md](COPY_DRAFT.md)。

## 为什么重做

旧版功能铺得很开（9 类健康记录、11 类护理记录、提醒和计划两套排期、五个各自产出建议的引擎），但没有一条把它们串起来的主线。结果是：

- 记录臃肿，日常真正会记的只有几项；
- 建议机械，大多是阈值规则加模板句，和这只狗自己的数据联系不紧；
- 计划和趋势各管各的，发现了问题也变不成行动。

v1 不是在旧版上继续修补，而是围绕一条核心循环重新组织。

## 用户与目标

- 作者本人和自家金毛，再加一两位社区朋友（养骑士查理王、泰迪，平时用英文）。
- 没有交付压力，目标是让自己用得舒服、满意。
- 软目标：**2026 年底前看到第一份年度回顾。**

## 核心循环

> 高频的事一键记 → 学会这只狗平时的节奏 → 和平时不一样时，用人话说出来并给一个具体动作 → 周期性的事按实际完成时间推算下一次 → 做完就是一条记录

新功能都先用这条循环检验：不在循环里的，先不做。

## 产品原则

- **温度和陪伴**：只累加做过的事，不打分、不显示完成率，也不提断开的日子。
- **不诊断**：只描述"和平时不一样"，需要时建议问兽医。
- **具体**：每条建议都有这只狗的数据或今天的实际情况作依据，没有依据就不说。
- **记录成本最低**：一键记一条，有异常再展开补充。

## 已定决策

### 记录

| 处理 | 项目 |
| --- | --- |
| 首页一键记录 | 饮食（预设每餐份量）、饮水（预设水碗容量，加满一次点一下）、排泄、梳毛、遛狗 |
| 定期 | 洗澡、美容修剪、广谱驱虫、心丝虫药、体重（称重周期可选：每周 / 每两周 / 每月 / 每季度）、耳朵检查 |
| 需要时 | 症状、用药、疫苗 |
| 合并为"其他护理"，用标签区分 | 刷牙、剪指甲、擦眼睛、足爪、环境清洁 |

- 健康记录和护理记录合并成**同一种记录**。
- 选项值一律以稳定的 code 存储（如 `stool: soft`），显示时再按语言翻译。
- 驱虫分两项。**广谱驱虫**可以勾选覆盖范围（体内、跳蚤蜱虫），复方药记一条就行。**心丝虫药**默认关闭，按兽医建议打开。

### 犬种分组

按"体型 + 毛发类型"分 7 组，决定默认显示哪些记录项、梳毛和洗澡的默认间隔、默认开启的护理项。分组和默认值见 [COPY_DRAFT.md 第 6 节](COPY_DRAFT.md#6-犬种分组--breed-groups)，用户可以随时修改。

### 计划

- 提醒和护理计划合并为一个"计划"。
- 下一次的时间从**实际上一次完成**往后推算，不按日历硬算。
- 支持一次性事项，比如看医生的预约。

### 每日卡片（观察引擎）

- 原来五个各自产出建议的引擎（tips、summary、dynamics、recommendation、coverage）合并为**一个观察引擎**，统一输出卡片。
- 每天 2–3 张，分四种：观察（和平时不一样）、该做了、小贴士（结合当天情况）、陪伴时刻。
- 记录不满一周，不出"观察"类卡片。
- 引擎只输出结构化的 key 和参数，不直接拼中文句子。
- 季节、品种、年龄段等静态内容不再单独出卡片，只作为生成卡片时的背景信息。

### 天气

- 使用 [Open-Meteo](https://open-meteo.com/)：不需要 API key，按城市名查询，不读取 GPS。
- 用户在设置里填一次城市，App 查到经纬度后保存，之后每天拉一次预报并缓存。
- 没填城市或网络失败时，不出天气贴士，其他功能不受影响。
- 按要求在 App 内注明数据来源。仅限非商业使用。

### 语言与单位

- 支持中文和英文。默认跟随系统语言，单位默认跟随地区（美国用 lb、cup、oz、°F、miles），都可以手动改。
- 数量相关的文案用 ICU 复数格式，比如 "1 day" 和 "2 days"。

### 陪伴回顾

- 有月度回顾和年度回顾，不再保留覆盖率页面。
- 年度回顾开头写："今年，你使用 App 共 x 天。在这 x 天里……" 这里的 x 是**有至少一条记录的天数**。
- 只展示正面或中性的数字。

## 保留、冻结与移除

| 处理 | 内容 |
| --- | --- |
| 保留并复用 | iOS / Android 原生配置与签名、本地通知、遛狗 Live Activity、相册引用与缩略图、`lib/core/ui`、drift 基础设施、测试工具 |
| 按新设计重写 | 数据结构、记录、计划、建议引擎、首页、时间线 |
| 冻结（保持现状，不扩展） | 时光 / 手账、本地知识库 |
| 移除 | 覆盖率页面与连续天数统计、旧提醒系统、独立的 tips / summary / dynamics 卡片 |

旧数据**不迁移**。v1 使用新的 bundle ID，开发期间旧 App 照常留在手机上使用。

## 开发方式

每个功能按固定顺序推进，**逻辑先行，UI 紧跟着落地**：

1. **契约**：先确定 domain model，以及它要回答用户的问题和需要的所有状态。
2. **逻辑和测试**：实现并用单元测试锁住行为，单独提交一次。
3. **UI**：按新的设计语言实现，再提交一次。

第 3 周之前确定设计语言，之后每个阶段做出来的界面都直接是新风格，最后不再统一翻新。

## 12 周排期

| 时间 | 阶段 | 完成时能看到 |
| --- | --- | --- |
| 10/10–10/11 | 收拾 | 当前改动提交；打 `legacy-v0` 标签；开 `v1` 分支 |
| 第 1–2 周 · 10/12–10/25 | 地基 | v1 数据结构（统一记录表、选项 code、犬种分组、语言和单位设置）；中英文 l10n 框架；切换到英文时界面全是英文 |
| 第 3–4 周 · 10/26–11/8 | 设计语言 + 记录 | 选定样稿；按新风格实现一键记录、份量和水碗预设、按犬种的引导设置；**开始日常使用** |
| 第 5–6 周 · 11/9–11/22 | 计划 | 提醒和计划合并；按实际完成时间推算下一次；犬种默认间隔；接上通知 |
| 第 7–9 周 · 11/23–12/13 | 观察引擎 | 学习日常节奏；每日卡片；接入天气；用上朋友们审读后的文案 |
| 第 10–11 周 · 12/14–12/27 | 陪伴回顾 | 月度和年度回顾；按新风格调整时间线 |
| 第 12 周 · 12/28–12/31 | 收尾 | 真机检查；看到第一份年度回顾 |

如果进度落后，**先缩小观察引擎的范围**，年度回顾不往后推。

## 验收要求（沿用）

- 记录只属于当前选中的狗；切换狗之后，不显示上一只狗的数据。
- 数据库写入成功后，才关闭表单或提示成功；写入失败时保留用户的输入。
- 按本地自然日 `[00:00, 次日 00:00)` 统计。
- 通知或相册权限失败时，不丢失已经保存的数据。
- 修改数据结构时提交 `drift_schemas/` 快照，并附带迁移测试（从 v1 开始算）。
