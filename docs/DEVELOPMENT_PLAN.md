> 更新日期：2026-09-12
> 当前阶段：P0 记录、护理计划、提醒、健康动态与轻量知识库收尾

## 1. 本轮目标与结果

本轮以最近几次提交为基线，把 P0 从“记录可用”推进到“记录、计划、提醒、通知和本地健康动态可串起来使用”。

当前工作区已实现：狗狗档案、健康/护理记录、照片头像、历史记录、日历回看、爱宠时光、护理计划、护理覆盖统计、提醒页、通知中心、系统本地通知、iOS 遛狗实时活动、本地健康动态建议、健康摘要和本地 SQLite 参考手册。就诊、处方、通用附件、导出、备份恢复、OCR 和 GPS 路线仍未进入完整实现。

| 就诊 / 复诊 | 新增菜单未开放该类型 | `VisitRepository`、就诊详情、复诊日期 |

| 护理计划 | 持久化、完成/跳过、覆盖统计和到期通知已接入；规则版本化仍可加强 | 规则版本、建议忽略记录、更多计划日志展示 |

## 4. 当前实现边界

- `user.sqlite` 当前包含狗狗档案、护理活动、健康记录、应用设置、狗狗照片、爱宠时光、相册引用、护理计划、护理计划日志、提醒和提醒日志。就诊、处方、附件和备份尚未建表。
- 爱宠时光只保存文字、Emoji 和系统相册引用；缩略图为可清理缓存，不把原图或视频写入数据库。
- 狗狗照片已经支持本地保存、读取、头像标记、说明修改、删除和级联清理；照片管理页已接入。
- 护理计划已持久化到数据库，重启后通过 `CarePlanController` 自动加载，并通过 `careCoverageProvider` 计算覆盖情况。
- 提醒数据、提醒页、通知中心和系统本地通知已接入；Web 调试端只保存提醒数据，不调度系统通知。
- 健康动态、健康摘要和建议均为本地确定性计算，不调用网络和大语言模型。
- 本地知识库是离线参考手册，用于观察、记录、护理和就医准备；不参与 AI 问答，也不提供处方、剂量或诊断。
- iOS Live Activity 只服务进行中遛狗状态；GPS 路线仍未接入。

## 5. 验收标准

- 创建或选择狗狗后，新增的健康/护理记录必须归属当前狗狗。
- 完全关闭并重新打开 App 后，狗狗、记录、当前狗狗和进行中的遛狗仍可恢复。
- 日历选择某天时，只显示该本地自然日 `[00:00, 次日 00:00)` 的记录。
- Repository 写入失败时不提前显示成功，也不自动关闭表单。
- 删除狗狗时继续由数据库外键级联清理健康与护理记录。
- 提醒完成、跳过、暂停或禁用后，提醒日志和通知中心状态需要同步更新。
- 通知权限被拒绝时，提醒仍可保存，页面应给出可恢复提示。
