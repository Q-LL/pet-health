# 毛健康开发计划

> 更新日期：2026-06-23  
> 当前阶段：本地数据接口接入与核心记录闭环

## 1. 本轮目标与结果

本轮以 `docs/LOCAL_DATA_API.md` 为接口基线，把现有 UI 中的静态入口接到 Repository，并优先完成“选择宠物 → 新增记录 → 持久化 → 日历回看”的最小闭环。

### 已完成

- [x] 宠物档案列表、当前宠物切换、创建、编辑、删除接入 `PetRepository`
- [x] 宠物表单补齐姓名、物种、品种、性别、生日、绝育、过敏和慢性病字段
- [x] 健康记录 8 种类型接入 `HealthRecordRepository.create`
- [x] 体重记录支持数值与 kg 单位，症状记录支持 1–5 严重程度
- [x] 护理记录 10 种类型接入 `CareRepository`
- [x] 洗澡使用便捷接口，遛狗支持开始、进行中恢复、结束和自动计算时长
- [x] 首页“体重”“更多记录”“新增记录”快捷入口接入真实表单
- [x] 首页根据当前宠物显示欢迎信息，无真实宠物时引导创建档案
- [x] 日历按日期查询并合并健康记录和护理记录，按发生时间排序
- [x] 保存操作等待数据库完成，失败时保留表单并显示错误

## 3. 当前仍缺失或不完整的接口

以下能力出现在产品蓝图或现有 UI 文案中，但目前没有可接入的 Repository/数据表接口：

| 能力 | 当前状态 | 需要的核心接口 |
|---|---|---|
| 提醒与通知 | UI 为静态占位 | `ReminderRepository`、重复规则、状态变更、提醒日志 |
| 就诊 / 复诊 | 新增菜单未开放该类型 | `VisitRepository`、就诊详情、复诊日期 |
| 处方 | 无数据层 | `PrescriptionRepository`、处方原文、结构化药品信息 |
| 通用附件 | 只有宠物照片，不能挂到记录上 | `AttachmentRepository` 与记录/就诊关联 |
| 护理计划 | 仅内存状态，重启会丢失 | `CarePlanRepository`、计划完成日志、到期计算 |
| 趋势提示 | 首页仅静态文案 | 聚合查询/趋势服务、规则结果持久化 |
| 健康摘要与导出 | 设置页占位 | 摘要聚合、PDF/CSV/JSON 导出接口 |
| 备份与恢复 | 无数据层 | 数据库与照片打包、校验、恢复、版本迁移 |
| 本地知识库 | 无 `knowledge.sqlite` | 知识条目、FTS 搜索、知识包版本接口 |
| OCR | 无接口 | 图片识别、候选字段、用户确认后的写入流程 |
| GPS 路线 | `routeFilePath` 只有字段 | 权限、轨迹采集、文件生命周期接口 |

已有接口但 UI 尚未完整接入：

- 宠物照片 Repository 已完整，但缺文件选择依赖和照片管理页面。
- 健康与护理 Repository 已支持单条读取、更新、删除、关键词筛选和分页；当前 UI 先完成创建与按日回看。
- 宠物 Repository 已支持关键词、物种筛选和分页；当前宠物页尚未提供搜索筛选控件。

## 4. 验收标准

- 创建或选择宠物后，新增的健康/护理记录必须归属当前宠物。
- 完全关闭并重新打开 App 后，宠物、记录、当前宠物和进行中的遛狗仍可恢复。
- 日历选择某天时，只显示该本地自然日 `[00:00, 次日 00:00)` 的记录。
- Repository 写入失败时不提前显示成功，也不自动关闭表单。
- 删除宠物时继续由数据库外键级联清理健康与护理记录。
