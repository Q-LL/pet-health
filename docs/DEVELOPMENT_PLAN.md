# 毛健康开发计划

> 更新日期：2026-06-23  
> 当前阶段：P0 记录管理闭环收尾

## 1. 本轮目标与结果

本轮以 `docs/LOCAL_DATA_API.md` 为接口基线，把现有 UI 中的静态入口接到 Repository，并优先完成“选择狗狗 → 新增记录 → 持久化 → 日历回看”的最小闭环。

当前工作区代码和文档已对齐到“可真实记录和回看”的阶段，不再只是 UI 骨架。`flutter analyze` 无问题，`flutter test` 已通过全部 30 个测试。

### 已完成

- [x] 狗狗档案列表、当前狗狗切换、创建、编辑、删除接入 `PetRepository`
- [x] 狗狗表单补齐姓名、类型/犬种、品种、性别、生日、绝育、过敏和慢性病字段
- [x] 健康记录 8 种类型接入 `HealthRecordRepository.create`
- [x] 体重记录支持数值与 kg 单位，症状记录支持 1–5 严重程度
- [x] 护理记录 10 种类型接入 `CareRepository`
- [x] 洗澡使用便捷接口，遛狗支持开始、进行中恢复、结束和自动计算时长
- [x] 首页“体重”“更多记录”“新增记录”快捷入口接入真实表单
- [x] 首页根据当前狗狗显示欢迎信息，无真实狗狗时引导创建档案
- [x] 日历按日期查询并合并健康记录和护理记录，按发生时间排序
- [x] 保存操作等待数据库完成，失败时保留表单并显示错误
- [x] 健康记录支持按天查看、编辑、删除与删除确认
- [x] 护理记录支持按天查看、编辑、删除与删除确认
- [x] 新增独立历史记录页，按日期平铺健康/护理记录，编辑和删除收敛到详情二级窗口
- [x] 日历页恢复为按天查看入口，不直接承载记录管理操作
- [x] 遛狗入口拆分为“手动补录”和“开始计时”；只有快速遛狗入口直接开始计时

## 2. 下一阶段计划

1. 先补齐已有 Repository 的 UI 能力，优先把首页、历史记录和照片管理从“能用”打磨到“日常可用”。

4. 趋势提示、健康摘要、知识库、OCR 和 GPS 路线放在后续迭代，不抢当前 P0 主线。

## 3. 当前仍缺失或不完整的接口

以下能力出现在产品蓝图或现有 UI 文案中，但目前没有可接入的 Repository/数据表接口：

| 能力 | 当前状态 | 需要的核心接口 |
|---|---|---|
| 提醒与通知 | UI 为静态占位 | `ReminderRepository`、重复规则、状态变更、提醒日志 |
| 就诊 / 复诊 | 新增菜单未开放该类型 | `VisitRepository`、就诊详情、复诊日期 |
| 处方 | 无数据层 | `PrescriptionRepository`、处方原文、结构化药品信息 |
| 通用附件 | 只有狗狗照片，不能挂到记录上 | `AttachmentRepository` 与记录/就诊关联 |
| 护理计划 | 仅内存状态，重启会丢失 | `CarePlanRepository`、计划完成日志、到期计算 |
| 趋势提示 | 首页仅静态文案 | 聚合查询/趋势服务、规则结果持久化 |
| 健康摘要与导出 | 设置页占位 | 摘要聚合、PDF/CSV/JSON 导出接口 |
| 备份与恢复 | 无数据层 | 数据库与照片打包、校验、恢复、版本迁移 |
| 本地知识库 | 无 `knowledge.sqlite` | 知识条目、FTS 搜索、知识包版本接口 |
| OCR | 无接口 | 图片识别、候选字段、用户确认后的写入流程 |
| GPS 路线 | `routeFilePath` 只有字段 | 权限、轨迹采集、文件生命周期接口 |

已有接口但 UI 尚未完整接入：

- 狗狗照片 Repository 已接入“上传并设为头像”，但还缺独立照片管理页、头像切换、说明修改和删除入口。
- 健康与护理 Repository 已支持单条读取、更新、删除、关键词筛选和分页；当前 UI 已完成创建、按日回看、编辑和删除，但还缺关键词筛选与分页控件。
- 狗狗 Repository 已支持关键词、犬种/体型筛选和分页；当前狗狗页尚未提供搜索筛选控件。

## 4. 当前实现边界

- `user.sqlite` 当前包含狗狗档案、护理活动、健康记录、应用设置和狗狗照片。提醒、就诊、处方、附件、护理计划和备份尚未建表。
- 狗狗照片已经支持本地保存、读取、头像标记、说明修改、删除和级联清理；当前 UI 只接入了“上传并设为头像”。
- 护理计划候选和开启状态目前由 Riverpod 内存状态维护，重启后不会保留。
- 首页“今日提醒”和“本地趋势提示”仍是产品目标展示，不代表已有提醒或规则引擎。

## 5. 验收标准

- 创建或选择狗狗后，新增的健康/护理记录必须归属当前狗狗。
- 完全关闭并重新打开 App 后，狗狗、记录、当前狗狗和进行中的遛狗仍可恢复。
- 日历选择某天时，只显示该本地自然日 `[00:00, 次日 00:00)` 的记录。
- Repository 写入失败时不提前显示成功，也不自动关闭表单。
- 删除狗狗时继续由数据库外键级联清理健康与护理记录。
